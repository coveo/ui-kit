In the experimental SSR sub-packages, definers take static options only and `fetchStaticState()` takes page facts only: `navigatorContext`, `accessToken`, `context`, `cart`, `searchParams`, `productId` and `recommendations` for commerce, and `navigatorContext`, `accessToken`, `searchParams` and `context` (the custom context values) for search. The per-request `controllers` option, `buildWithProps()`, the `...WithProps` and `...WithoutProps` definition types, `InferControllerPropsMapFromDefinitions`, `ControllersPropsMap`, `EngineDefinitionControllersPropsOption`, `MissingControllerProps` and `controllerProps` in the static state are removed, and the static state carries `state` only per controller. `defineProductEnrichment()` takes its placements as static options and seeds the badges with `productId`; `defineRecommendations()` seeds its slot the same way. The search `context` controller is included in every search definition, like `parameterManager`, so `defineContext()`, `defineSearchParameterManager()` and `defineUrlManager()` leave the search sub-package, and `defineCart()`, `defineContext()` and `defineParameterManager()` leave the commerce sub-package. See the upgrade guide, "Controller props" and "Search context".
