In the experimental commerce SSR sub-package, `enableResults` is set once on the engine definition, as `true` or as `{search, listing}`, and applies to the listing and search requests that the controllers of the definition send: product list, pagination, sort, facets, summary, breadcrumbs, parameter manager, search box, recent queries list, did-you-mean, query trigger and filter suggestions all build their requests with the flag of the definition, as does the first request of `fetchStaticState()`. Requests dispatched through action loaders take their own `enableResults`. The flag leaves `defineProductList()`, `defineSearchBox()`, `defineRecentQueriesList()`, `defineDidYouMean()` and `defineQueryTrigger()`, and `ProductListOptions` and `DidYouMeanOptions` leave the sub-package. `buildFilterSuggestionsGenerator()` takes an `enableResults` option, like `buildSearch()`, so the search that a selected filter suggestion triggers can fill `results`. See the upgrade guide, "`enableResults`".
