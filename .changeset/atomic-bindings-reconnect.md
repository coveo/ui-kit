'@coveo/atomic': patch
---

Components that use the `@bindings()` decorator now handle reconnection and setup errors better. A component removed from the page and added back requests its bindings once, keeps updating when the language changes, and no longer piles up context consumers. When a component's setup throws, the error is logged once and the component updates. A component placed outside of an Atomic interface now logs an error to the console on each connection, while a component slotted into an interface through another shadow root is no longer treated as outside of it. Components that use `InitializeBindingsMixin` now log a failed bindings fetch to the console, and fetch their bindings again on reconnection after a failed fetch. A component is no longer reported as outside of an interface when a wrapper renders the slot that places it in one after it connects. The public `initializeBindings` function, which custom components call, now finds an interface through slotted content, and rejects with `MissingInterfaceParentError` one task later instead of right away.
